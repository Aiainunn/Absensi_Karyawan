2. Keputusan Tim
Keputusan berikut sudah disepakati dan menjadi dasar perubahan pada checklist tiap peran.
No
Topik
Keputusan
1
Penulis REST API
Ditulis oleh Peran 1, termasuk migrasi Flutter dari local_db_service.dart ke pemanggilan HTTP. Peran 2 mengemas source tersebut ke dalam container.
2
Autentikasi JWT
Access token JWT (HS256) berisi id dan role, ditandatangani dengan JWT_SECRET yang sama di kedua instance melalui .env. Tidak ada session di memori server (stateless), password disimpan dengan hash bcrypt, dan middleware memeriksa header Authorization: Bearer.
3
HTTPS
Frontend memakai domain/subdomain dan sertifikat Let's Encrypt di Nginx. Port 80 dialihkan ke 443. HTTPS diperlukan agar kamera/selfie berfungsi di browser.
4
Akses DBeaver
Lewat SSH tunnel melalui vm-backend. Port 3306 tetap tertutup dari internet.
5
Pengujian backend
Pengujian langsung ke port 5001/5002 dilakukan dari dalam VM (curl). Dari luar, API hanya diuji melalui https://<domain>/api.

4. Peran 1: Cloud Engineer (Frontend, Load Balancer & REST API)
Fokus VM
vm-frontend-lb (AWS EC2, Ubuntu 22.04 LTS, t3.micro, 20 GB gp3).
Tools
AWS Console (EC2, Elastic IP, Security Group), Termius (SSH), Nginx, Certbot, Git, Flutter SDK (di laptop), Node.js (rekomendasi untuk REST API), UFW.
Input yang dibutuhkan
IP privat vm-backend dan alokasi port 2 instance backend dari Peran 2 (contoh: 5001 dan 5002).
Struktur tabel dan kredensial app_user dari Peran 3 untuk pengembangan API.
Daftar IP publik anggota dan key pair AWS (.pem) dari koordinator tim.
Domain atau subdomain untuk HTTPS (lihat Lampiran B).
Output yang diserahkan
Domain HTTPS dan Elastic IP vm-frontend-lb; port 80 dialihkan ke 443.
Source code REST API (termasuk JWT) dan dokumentasi endpoint untuk Peran 2, 4, 5.
Flutter web build yang sudah memakai API.
File konfigurasi Nginx (SSL, SPA, upstream round-robin) dan bukti log akses yang menunjukkan distribusi request ke backend.

Lampiran B: Asumsi dan Hal yang Perlu Dikonfirmasi
Domain: belum ada keputusan sumber domain. Opsi gratis adalah subdomain DuckDNS atau No-IP; Let's Encrypt tidak dapat menerbitkan sertifikat untuk alamat IP saja.
Stack backend: Node.js (Express) hanya rekomendasi. Peran 1 dapat memilih stack lain selama dapat dikemas dengan Docker.
Beban Peran 1: peran ini kini paling berat. Jika perlu, penulisan API dapat dibagi dengan Peran 2 tanpa mengubah dokumen ini secara besar.
Dokumen rujukan docs/02-tabel-ip-port.md, docs/03-skenario-pengujian.md, dan docs/04-kerangka-laporan.md belum tersedia dan perlu dibuat atau diunggah.
Nama anggota untuk tiap peran belum diisi (kolom Penanggung Jawab pada bagian 1).
Firewall: karena Docker melewati UFW, uji port scanning membuktikan Security Group, bukan UFW.
